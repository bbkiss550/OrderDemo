# ผลตรวจความสมบูรณ์ FoodFlow — 19 ตุลาคม 2026

ระบบหลักผ่านการทดสอบสำหรับทดลองใช้งานบน localhost ครอบคลุมรับลูกค้า เปิดบิล QR สั่งอาหาร คิวอาหารครัว ชำระเงิน และรายงาน ยังต้องทดสอบมือถือ/เครื่องพิมพ์จริงและเตรียมการดูแลระบบก่อนใช้กับร้านจริง ขอบเขตที่ยังไม่มีแสดงแยกด้านล่าง

## วิธีตรวจและการคงข้อมูลร้าน

- แอปจริง `localhost:8088` และ PostgreSQL health UP ใช้ Docker image ของโค้ดปัจจุบัน
- สร้าง pg_dump ปัจจุบันเป็น private backup ใน `.runtime/backups/` แล้ว restore ลงฐานข้อมูล QA แยก เปรียบเทียบ snapshot กับต้นฉบับก่อนทดสอบ
- ชุดทดสอบที่สลับ VAT/รับชำระเงินและสร้าง fixture ทั้งหมดทำกับแอป QA อีก container/port ไม่ทำกับข้อมูลร้านจริง
- หลังตรวจ เปรียบเทียบ snapshot ของการตั้งค่าร้าน โต๊ะ บิล/รายการบิล แพ็กเกจ เมนู บัญชีพนักงาน และออเดอร์/รายการอาหารกับก่อนตรวจแล้วตรงกัน ปิดและลบ container/network/ฐานข้อมูล QA ของรอบนี้แล้ว เก็บเฉพาะ backup และผลตรวจ private
- ตรวจ frontend ด้วย jsdom โดยโหลด HTML/scripts/assets และ API จริง ไม่ถือเป็นการยืนยันภาพในเบราว์เซอร์หรือสัมผัสบน iPad จริง

## จุดที่แก้ในรอบตรวจ

1. **หน้าออเดอร์ของบัญชีครัวผ่านลิงก์ตรง:** route อนุญาต แต่ sidebar ไม่แสดงลิงก์นั้น การเรียก classList บน nav ที่ไม่มีทำให้ JavaScript หยุด แก้ให้ตรวจว่ามี nav ก่อน และเพิ่มกรณีนี้ใน order-smoke ตรวจซ้ำผ่านแล้ว นำ image ที่แก้ขึ้น localhost แล้ว
2. **ชุดทดสอบ billing เก่า:** เดิมตรวจคำต้อนรับ/หมดเวลาจาก HTML ที่ render ฝั่งเซิร์ฟเวอร์ ซึ่งเปลี่ยนเป็นหน้า Quick Order แล้ว ปรับตรวจ public state API ของบิลจริงและ customer script ชุดเต็มผ่านทั้ง VAT/checkout/QR ตามเดิม
3. **คู่มือกู้ไฟล์สำรอง 8 ตุลาคม:** คำสั่งเก่าติด `schema public already exists` บนฐานข้อมูลใหม่ แก้คำสั่งใน `db/README.md` ให้ใช้ clean/if-exists เฉพาะฐานข้อมูล restore ใหม่ที่ว่าง แล้วทดสอบผ่านจริง ไม่รัน restore กับฐานข้อมูลร้าน

## Backup และ migration

- สำรองฐานข้อมูลปัจจุบันและ restore ลงฐานข้อมูล QA ได้ เปรียบเทียบข้อมูลก่อนทำ fixture ผ่าน
- ไฟล์ที่เก็บใน Git `db/dump-db_order_demo-202610081600.backup` restore ได้เมื่อใช้คำสั่งที่แก้แล้ว และอัปเกรด 005/006 ผ่าน
- ตรวจการคงบิล legacy/สิทธิ์เมนูหลัง 004 และ constraint หนึ่งแพ็กเกจ/ผู้ใหญ่–เด็กด้วยสคริปต์ migration ผ่าน
- ติดตั้ง SQL 001–006 ใหม่ใน schema ทดสอบแยกผ่าน ยังไม่มี auto migration ตาม requirement
- การ restore นี้ตรวจการกู้และ schema ในฐานข้อมูลทดสอบ ไม่ได้จำลองเครื่องเสียทั้งเครื่อง เวลากู้คืนสูงสุด หรือการสำรองอัตโนมัติรายวัน

## ก่อนใช้งานกับร้านจริง

1. **LAN และอุปกรณ์:** Docker ปัจจุบัน bind 127.0.0.1 ตามการใช้งาน localhost ต้องกำหนด APP_BIND/URL ร้านให้มือถือเข้าถึง สร้างบิลใหม่ตาม URL ที่ถูกต้อง แล้วทดสอบ iPad และ QR จากโทรศัพท์จริง รวมหลายเครื่อง/สัญญาณหลุด
2. **เครื่องพิมพ์:** ตรวจ print preview และกระดาษจริงของใบเปิดบิล ใบสั่งอาหาร และรายงาน เลือกขนาด/ขอบกระดาษ ปิดหัว–ท้ายเบราว์เซอร์ และยืนยันว่าครัวอ่านได้ การทดสอบรอบนี้ยังไม่ได้ส่งงานไปเครื่องพิมพ์จริง
3. **การดูแลระบบ:** เปลี่ยนรหัสผ่านทดสอบของแอดมินก่อนใช้จริง วางแผน backup อัตโนมัติและเก็บนอกเครื่อง ตรวจการกู้คืนเป็นระยะ ปัจจุบัน compose ยังไม่มี restart policy และยังไม่ได้ทดสอบโหลด/เปิดต่อเนื่องเป็นเวลานาน
4. **เก็บงานใน Git:** checkout ยังมีงานที่แก้และไฟล์ใหม่ซึ่งยังไม่ commit การตรวจครั้งนี้ไม่ได้ commit/push ให้
