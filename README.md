# FoodFlow

ระบบแอดมิน: ตั้งค่าร้าน แพ็กเกจเด็ก/ผู้ใหญ่ หมวดหมู่และเมนูอาหารแยกแพ็กเกจ ผังโต๊ะหลายชั้น เปิดบิล ย้ายบิล ออก QR พิมพ์ใบเปิดบิล และบันทึกชำระเงิน ตาม `KICKOFF.md`

ใช้ Sneat 1.0.0, Spring Boot, Thymeleaf, Bootstrap 5, PostgreSQL และ Java 21 บน Docker

## Docker: ใช้ฐานข้อมูลเดิมบน Windows

คัดลอก `.env.example` เป็น `.env` แล้วระบุรหัสผ่านฐานข้อมูลและ ADMIN_PASSWORD (ไฟล์นี้ไม่เข้า Git และไม่เข้า Docker image)

สำหรับฐานข้อมูลใหม่ รัน SQL ทั้งสี่ไฟล์ตามลำดับด้วยตนเองก่อนเริ่มแอป:

```powershell
& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' -h localhost -p 5432 -U postgres -d db_order_demo -W -v ON_ERROR_STOP=1 -f .\sql\001_admin.sql
& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' -h localhost -p 5432 -U postgres -d db_order_demo -W -v ON_ERROR_STOP=1 -f .\sql\002_floor_plan.sql
& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' -h localhost -p 5432 -U postgres -d db_order_demo -W -v ON_ERROR_STOP=1 -f .\sql\003_menu_catalog.sql
& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' -h localhost -p 5432 -U postgres -d db_order_demo -W -v ON_ERROR_STOP=1 -f .\sql\004_single_package_bills.sql
```

ไฟล์เหล่านี้รันครั้งเดียว ในเครื่องปัจจุบันรันทั้งสี่แล้ว ฐานข้อมูลเดิมให้รันเฉพาะไฟล์ที่ยังไม่ได้รันตามลำดับ ก่อนใช้โค้ดรุ่นใหม่ หยุดแอปก่อนอัปเกรด schema และสำรองฐานข้อมูลด้วย pg_dump

```powershell
docker compose up --build -d
```

ตรวจสุขภาพแอปและการเชื่อมต่อฐานข้อมูลที่ `http://localhost:8088/actuator/health` (เปลี่ยนพอร์ตได้ผ่าน APP_PORT ใน .env)
เข้าสู่ระบบที่ `http://localhost:8088/login` ด้วยชื่อ ADMIN_USERNAME (ค่าเริ่มต้น `admin`) และรหัสผ่าน ADMIN_PASSWORD ใน `.env` บัญชีของเครื่องนี้ตั้งค่าตามที่ผู้ใช้ระบุ

## การใช้งาน

1. ตั้งค่าร้าน: ชื่อร้าน VAT แบบรวม/แยก อัตรา VAT เวลามาตรฐาน ค่าปรับ และขนาดกระดาษ มีตัวอย่างความกว้างกระดาษใน Modal
2. กำหนดแพ็กเกจ เช่น Standard/Deluxe/Premium แต่ละแพ็กเกจมีราคาผู้ใหญ่และเด็กในรายการเดียว ปิดใช้งานแพ็กเกจได้โดยไม่กระทบบิลเดิม
3. เลือกโต๊ะว่างและแพ็กเกจหนึ่งรายการ ระบุจำนวนผู้ใหญ่/เด็กแยกกัน แล้วเปิดบิล เวลาเริ่มทันทีที่บันทึกสำเร็จ
4. พิมพ์ใบเปิดบิลจากรายละเอียดบิล เลือกกระดาษใน driver เครื่องพิมพ์ให้ตรงกับความกว้างที่ตั้งในร้าน และปิด browser header/footer
5. เช็คบิลเมื่อทานเสร็จ หากเกินเวลาจะเลือกค่าปรับไว้ก่อน พนักงานยกเว้นได้ เลือกช่องทางรับเงินแล้วปิดบิล

ราคาตัวอย่าง: Standard ผู้ใหญ่ 399 / เด็ก 199 บาท, Deluxe 599 / 399 บาท, Premium 899 / 699 บาท VAT รวมในราคา 7%, ระยะเวลา 90 นาที, ค่าปรับ 100 บาทต่อบิล ปรับได้ในแอดมิน

บิลเก็บชื่อร้าน ราคาแพ็กเกจ VAT ระยะเวลา ค่าปรับ และ URL ของ QR ณ ตอนเปิดบิล เมื่อย้ายบิลชื่อโต๊ะเปลี่ยนเป็นโต๊ะปัจจุบัน พร้อมเก็บประวัติโต๊ะเดิม ขนาดกระดาษใช้ค่าร้านปัจจุบันเพื่อพิมพ์ซ้ำได้ในเครื่องพิมพ์ที่เปลี่ยนขนาด

## หมวดหมู่และเมนูอาหาร

เปิด `/admin/categories` เพื่อเพิ่ม/แก้ไขชื่อ ลำดับ และสถานะหมวดหมู่ มีหมวดหมู่เริ่มต้น 8 หมวดตามภาพอ้างอิง การปิดหมวดหมู่หยุดขายอาหารทั้งหมดในหมวด แต่คงสถานะเปิด/ปิดรายเมนูไว้ เมื่อเปิดหมวดใหม่อาหารที่ปิดเองจะยังปิดอยู่

เปิด `/admin/menu` แล้วกด **เพิ่มเมนูอาหาร** ระบุชื่อ หมวดหมู่ คำอธิบาย ไอคอนอาหาร ลำดับ และสถานะขาย เปิดสวิตช์แพ็กเกจที่สั่งได้ เช่น Standard และ Premium หน้ารายการมีคอลัมน์สวิตช์แยกแต่ละแพ็กเกจ เปลี่ยนสิทธิ์หนึ่งแพ็กเกจโดยไม่เปลี่ยนแพ็กเกจอื่น ปิดทุกแพ็กเกจได้เพื่อเก็บอาหารที่ยังไม่พร้อมขาย ค่าบริการคิดจากแพ็กเกจในบิล ไม่มีการคิดราคาอาหารรายจานในระยะนี้

อัปโหลด JPG/PNG ไม่เกิน 2 MB และขนาดไม่เกิน 4096×4096 พิกเซล รูปเก็บใน PostgreSQL จึงคงอยู่เมื่อ rebuild/recreate Docker เปลี่ยนหรือเอารูปออกเพื่อใช้ Emoji ได้ การแก้ข้อความโดยไม่เลือกไฟล์ใหม่จะเก็บรูปเดิมไว้

ค้นหาชื่อ/คำอธิบาย/หมวดหมู่อัตโนมัติ กรองตามหมวดหมู่หรือแพ็กเกจ และเปิด–ปิดขายผ่านสวิตช์ได้ หากรายการถูกแก้ไขพร้อมกัน ระบบปฏิเสธข้อมูลเก่าให้โหลดล่าสุดก่อนบันทึก ใช้ Modal/AJAX และไม่ใช้ query parameters

เริ่มต้นไม่มีอาหารจริง ให้แอดมินเพิ่มรายการและเลือกแพ็กเกจของร้านเอง ระยะนี้เป็นหน้าจัดการข้อมูลอาหาร; การนำสิทธิ์แพ็กเกจไปตรวจออเดอร์ลูกค้าจะต่อในระยะหน้าสั่งอาหาร/ครัว

## การใช้ผังโต๊ะ

เมนู **รับลูกค้าและเช็คบิล** (`/admin/reception`) ใช้ดูผังและสถานะโต๊ะเต็มความกว้าง ไม่มีคำอธิบายด้านข้างหรือกล่องแถว/คอลัมน์ กดโต๊ะเพื่อเปิดป็อปอัพสำหรับเปิดบิล ดู QR ย้ายบิล และเช็คบิล แสดงข้อมูลล่าสุดทุก 15 วินาทีขณะที่ไม่ได้เปิด Modal ไม่มีเครื่องมือแก้ผังในหน้านี้

ช่องในผังเป็นสี่เหลี่ยมจัตุรัส ขนาดปรับตามความกว้างพื้นที่ หากผังมีขนาดใหญ่สามารถเลื่อนดูภายในผังได้

เมนู **จัดการผังโต๊ะ** (`/admin/floor-plan`) เปิดเป็นหน้าออกแบบโดยตรง เพิ่มชั้น ตั้งชื่อและขนาดตาราง (1–100 แถว/คอลัมน์) ได้เอง ลากเลือกช่องว่างแล้วสร้างโต๊ะ ระบุชื่อและจำนวนที่นั่งแยกจากพื้นที่ เช่น 1 ช่อง 2 ที่นั่ง หรือ 3 ช่อง 1 ที่นั่ง เลือกเพิ่มหลายพื้นที่เพื่อสร้างรูปทรงอิสระได้ กด **บันทึกผัง** เพื่อใช้งานจริง มีคำเตือนก่อนออกจากหน้าหากผังยังไม่บันทึก

กดโต๊ะในโหมดออกแบบเพื่อแก้ชื่อ/ที่นั่ง หรือ **กำหนดพื้นที่ใหม่** ซึ่งคงจำนวนที่นั่งเดิม การนำออกจากผังยังเก็บโต๊ะและประวัติบิลไว้ สามารถวางใหม่ผ่าน **วางโต๊ะที่มีอยู่แล้ว** โต๊ะที่มีบิลเปิดอยู่จัดพื้นที่ใหม่ได้ แต่ต้องย้ายหรือปิดบิลก่อนแก้ชื่อ/ที่นั่งหรือนำออกจากผัง

ในโหมดรับลูกค้า: เขียวว่าง เทาไม่ว่าง แดงปิดรับ/ปรับปรุง โต๊ะเกินเวลายังเป็นสีเทาพร้อม ◷ และข้อความหมดเวลา กดช่องใดของโต๊ะเพื่อเปิดบิล ดู QR เช็คบิล หรือย้ายบิลได้ สถานะอัปเดตทุก 15 วินาทีขณะไม่มี Modal เปิด

ย้ายบิลไปโต๊ะว่างที่เปิดรับและมีที่นั่งเพียงพอได้ทั้งในชั้นเดียวกันและข้ามชั้น ราคา เวลา และ QR คงเดิม หน้า QR และใบเปิดบิลที่พิมพ์ใหม่แสดงโต๊ะปัจจุบัน รายละเอียดบิลแสดงประวัติโต๊ะต้นทาง/ปลายทาง เวลา และผู้ย้าย ไม่มีการรวมบิล โต๊ะเดิมว่างแล้วสามารถปิดปรับปรุงพร้อมระบุสาเหตุได้

ระบบตรวจพื้นที่ทับกัน/หลุดขอบเขต ขนาดผังที่ตัดโต๊ะ และข้อมูลที่ถูกแก้ไขพร้อมกัน หากมีคนบันทึกก่อนต้องโหลดผังล่าสุดแล้วแก้ใหม่

QR เป็นรหัสสุ่มแยกบิล เปิดดูข้อมูลการใช้บริการได้จริง สถานะหมดเวลา/ปิดบิลตรวจจากเซิร์ฟเวอร์ ระยะนี้ยังไม่มีเมนูสั่งอาหารหรือ KDS หน้าลูกค้าจะแจ้งให้สั่งกับพนักงาน

## ทดสอบ QR จากโทรศัพท์ในร้าน

ค่าเริ่มต้นเปิดพอร์ตเฉพาะเครื่องนี้ (`127.0.0.1`) ก่อนใช้งานใน LAN ให้ตั้ง APP_BIND เป็น IP เครือข่ายร้านของเครื่องใน `.env` และตั้ง URL ในแอดมินเป็น `http://IP-เครื่อง:8088` ที่โทรศัพท์เข้าถึงได้ จากนั้นสร้างบิลใหม่ QR ของบิลเดิมยังใช้ URL เดิม

## Docker: ใช้ PostgreSQL ใน container

```powershell
docker compose -f compose.yml -f compose.database.yml up --build -d
```

ตัวเลือกนี้สร้างฐานข้อมูลแยกจาก PostgreSQL บนเครื่อง ข้อมูลเก็บใน named volume ไม่ได้คัดลอกข้อมูลจากฐานเดิม และไม่เปิดพอร์ต PostgreSQL ออกมาที่เครื่อง

สำหรับครั้งแรก ให้เริ่มเฉพาะฐานข้อมูลแล้วรัน SQL ด้วยตนเองก่อนเริ่มแอป:

```powershell
docker compose -f compose.yml -f compose.database.yml up -d database
Get-Content -Raw .\sql\001_admin.sql | docker compose -f compose.yml -f compose.database.yml exec -T database psql -U postgres -d db_order_demo -v ON_ERROR_STOP=1
Get-Content -Raw .\sql\002_floor_plan.sql | docker compose -f compose.yml -f compose.database.yml exec -T database psql -U postgres -d db_order_demo -v ON_ERROR_STOP=1
Get-Content -Raw .\sql\003_menu_catalog.sql | docker compose -f compose.yml -f compose.database.yml exec -T database psql -U postgres -d db_order_demo -v ON_ERROR_STOP=1
Get-Content -Raw .\sql\004_single_package_bills.sql | docker compose -f compose.yml -f compose.database.yml exec -T database psql -U postgres -d db_order_demo -v ON_ERROR_STOP=1
docker compose -f compose.yml -f compose.database.yml up --build -d app
```

## SQL และการหยุดระบบ

ไม่มีการสร้าง schema หรือรัน SQL อัตโนมัติ ต้องรัน SQL ด้วยตนเองตามข้อกำหนด

```powershell
docker compose down
```

หากใช้ฐานข้อมูล container ให้ใช้ `-f compose.yml -f compose.database.yml` กับคำสั่ง down ด้วย ข้อมูลยังคงอยู่ใน volume

## การตรวจสอบ

- Docker build รัน unit tests เรื่อง VAT รวม/แยกผ่าน Maven
- `node scripts/menu-smoke.cjs` ตรวจหมวดหมู่/เมนู/แพ็กเกจ CRUD, validation, CSRF, version ชนกัน, เปิด–ปิดขาย, การปิดหมวดหมู่ และรูปอัปโหลด/คงอยู่/ลบ เก็บและล้างเฉพาะข้อมูลทดสอบของตน
- `node scripts/floor-smoke.cjs` ตรวจผัง/พื้นที่/ที่นั่งอิสระ การแก้ไขชนกัน โต๊ะปิดรับ ย้ายบิล ประวัติ QR/ราคา/เวลาคงเดิม และย้ายพร้อมกันไปโต๊ะเดียว สร้างและล้างเฉพาะชั้น โต๊ะ และบิลทดสอบของตน
- `node scripts/package-smoke.cjs` ตรวจหนึ่งแพ็กเกจต่อบิล ราคาผู้ใหญ่/เด็ก snapshots, จำนวนศูนย์/ลบ/เกินความจุ, แพ็กเกจปิด, บิลผู้ใหญ่ล้วน/เด็กล้วน, สวิตช์อาหารแยกแพ็กเกจ และ version/CSRF
- `scripts/migration-single-package-check.sql` รันกับ psql เพื่อตรวจ schema ติดตั้งใหม่/การคงบิลเก่า/การย้ายสิทธิ์เมนูและ constraint ใน schema ทดสอบแยก ล้าง schema ของตนเมื่อผ่าน
- `node scripts/smoke-test.cjs` ตรวจ auth, CSRF, validation, หนึ่งแพ็กเกจพร้อมผู้ใหญ่/เด็ก, snapshot ราคา/VAT, idempotency, concurrent opening, QR, ใบเปิดบิล, หมดเวลา, ค่าปรับ, การปิดบิล และสร้าง QR ใหม่ ใช้ฐานข้อมูลเดิมบน Windows และล้างเฉพาะข้อมูลที่สคริปต์สร้างเอง
- บัญชีระยะแรกมี ADMIN จาก environment; การจัดการพนักงานและสิทธิ์แยกบทบาทอยู่ในระยะถัดไป
